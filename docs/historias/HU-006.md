# HU-006: Generar casos de prueba con IA desde una historia
**Épica:** E3 Generación de casos con IA · **Prioridad:** alta · **Estimación:** 5 pts

**Como** QA
**Quiero** generar una primera versión de casos de prueba a partir de una historia
**Para** no escribirlos desde cero y enfocarme en revisarlos

## Criterios de aceptación
- [ ] Dado el detalle de una historia, cuando hace clic en "Generar casos", entonces ve un indicador de carga y luego los casos generados en estado **Pendiente**.
- [ ] Dado un caso generado, cuando lo ve, entonces tiene: título, precondiciones, pasos, resultado esperado, **técnica** (partición, valor límite, tabla de decisión, negativo, flujo feliz, otra) y **prioridad** (alta / media / baja).
- [ ] Dada una generación, cuando termina, entonces cada criterio de aceptación de la historia queda cubierto por al menos un caso, y cada caso indica qué criterio(s) cubre.
- [ ] Dada una historia con casos, cuando vuelve a generar, entonces se reemplazan **solo los casos Pendientes**; los Aprobados y los editados se conservan. Antes ve una confirmación que lo explica.
- [ ] Dado que el proveedor de IA falla o no responde en 60 segundos, cuando genera, entonces ve "No se pudieron generar los casos, intentá de nuevo" y no se pierde ningún caso existente.
- [ ] Dado que se alcanzó el límite del free tier del proveedor, cuando genera, entonces ve "Se alcanzó el límite de generación, intentá más tarde".

### API
- [ ] `POST /api/stories/:id/generate-cases` responde **201** con los casos generados.
- [ ] Si el proveedor falla responde **502**; si hay rate limit, **429**.

### Técnico
- [ ] El proveedor se elige con `AI_PROVIDER` (`fake` | `groq`). En `fake` la respuesta es fija y determinística (para tests).
- [ ] La respuesta de la IA se valida contra un esquema antes de guardar; si no cumple, se trata como error del proveedor.
- [ ] La API key de Groq vive en variables de Railway; nunca en el repo ni en logs.
