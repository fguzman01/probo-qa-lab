# HU-003: Crear una historia de usuario
**Épica:** E2 Historias de usuario · **Prioridad:** alta · **Estimación:** 3 pts

**Como** QA
**Quiero** cargar una historia de usuario con sus criterios de aceptación
**Para** usarla como base para diseñar sus casos de prueba

## Criterios de aceptación
- [ ] Dado el formulario de nueva historia, cuando completa título, "Como", "Quiero", "Para" y al menos un criterio de aceptación, y guarda, entonces la historia se crea, es redirigido a `/historias/:id` y ve el código asignado, el título, Como/Quiero/Para y los criterios en el orden en que los cargó.
- [ ] Dada una historia nueva, cuando se guarda, entonces recibe un código `HU-` + número de al menos 3 dígitos (`HU-001` … `HU-999`, `HU-1000`), mayor que el de cualquier historia creada antes y distinto de todos. Puede haber huecos en la numeración.
- [ ] Dado el formulario, cuando intenta guardar con el título, "Como", "Quiero", "Para" o algún criterio vacío o con solo espacios, entonces ve "Campo obligatorio" debajo de cada campo vacío y no se envía ningún request.
- [ ] Dado el formulario, cuando gestiona los criterios, entonces arranca con 1 criterio, puede agregar hasta 30 (con 30, "Agregar criterio" se deshabilita), moverlos con ↑/↓ y quitar cualquiera salvo el último (con uno solo, "Quitar" queda deshabilitado). Al guardar, el detalle los muestra como CA1…CAn en ese orden.
- [ ] Dado cualquier campo de texto, cuando supera su máximo (título 120, "Como" 200, "Quiero", "Para" y cada criterio 500), entonces puede seguir escribiendo, ve el contador `n / máx` y, en vivo, "Máximo N caracteres" debajo del campo, y "Guardar historia" no envía el request mientras haya errores. El largo se cuenta en caracteres (un emoji = 1) después de recortar los espacios.
- [ ] Dado el formulario, cuando hace clic en "Cancelar", entonces vuelve a `/historias` sin confirmación y no se crea nada.
- [ ] Dado que hizo clic en "Guardar historia", mientras espera la respuesta, entonces el botón queda deshabilitado con "Guardando…" (un doble clic crea una sola historia).
- [ ] Dado que la sesión expiró mientras completaba el formulario, cuando guarda, entonces es redirigido al login con "Tu sesión expiró. Iniciá sesión de nuevo." (no se guarda borrador).

### API
- [ ] `POST /api/stories` válido responde **201** con la historia completa (ver `api.md`). `criteria[].position` respeta el orden enviado y `code` cumple el formato del segundo criterio.
- [ ] Body inválido responde **400** `VALIDATION_ERROR` con un solo `details` por campo inválido (los criterios como `criteria.<índice>.text`). Un texto de solo espacios cuenta como vacío. Valida los mismos límites que la UI y entre 1 y 30 criterios.
- [ ] Los textos se guardan recortados (`trim`). Los campos extra del body (`code`, `number`, `ownerId`, `position`) se ignoran: `ownerId` sale del token y `position` del orden del array.
- [ ] `DELETE /api/stories/:id` responde **204** y borra en cascada, o **404** si no existe. No tiene UI: sirve para limpiar los datos de prueba.

## Notas
- **Decisión:** el código lo asigna el sistema; el usuario no lo edita.
- **Decisión:** "Como / Quiero / Para" son 3 campos separados (no texto libre), para poder pasarlos estructurados a la IA.
- **Decisión (análisis):** HU-003 entrega una vista de detalle mínima en `/historias/:id`; HU-004 la completa (casos, botón Editar).
- **Decisión (análisis):** el mensaje de obligatorio es "Campo obligatorio" en todos los campos, igual que el login. El diseño UI muestra otros textos ("El título es obligatorio", "El criterio no puede estar vacío"): manda la HU.
