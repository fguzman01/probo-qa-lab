# HU-001: Iniciar sesión
**Épica:** E1 Acceso · **Prioridad:** alta · **Estimación:** 3 pts

**Como** QA usuario de Probo
**Quiero** iniciar sesión con mi email y contraseña
**Para** acceder a mis historias y casos de prueba de forma privada

## Criterios de aceptación
- [ ] Dado un usuario registrado, cuando ingresa email y contraseña correctos, entonces entra a la app y ve el listado de historias.
- [ ] Dado un usuario registrado, cuando ingresa una contraseña incorrecta, entonces ve el mensaje "Email o contraseña incorrectos" y sigue en el login.
- [ ] Dado un email que no existe, cuando intenta ingresar, entonces ve el mismo mensaje "Email o contraseña incorrectos" (no se revela si el email existe).
- [ ] Dado el formulario de login, cuando envía con email o contraseña vacíos, entonces ve un mensaje de campo obligatorio en cada campo vacío y no se llama a la API.
- [ ] Dado el formulario de login, cuando ingresa un email con formato inválido, entonces ve "Email inválido".
- [ ] Dado un usuario con sesión iniciada, cuando recarga la página, entonces sigue con la sesión activa.
- [ ] Dada una sesión iniciada, cuando pasan 8 horas, entonces la sesión expira y debe volver a iniciar sesión.

### API
- [ ] `POST /api/auth/login` con credenciales válidas responde **200** con un token JWT.
- [ ] Con credenciales inválidas responde **401** con `{ "error": "INVALID_CREDENTIALS" }`.
- [ ] Con body incompleto o email mal formado responde **400**.

## Notas
- **Decisión:** no hay registro en el MVP; los usuarios se crean por seed (uno de tests en dev, uno de smoke en prod).
- **Decisión:** contraseña guardada con hash (bcrypt/argon2), nunca en texto plano.
- **Decisión:** el token se guarda en `localStorage` (simple para el MVP; cookie httpOnly queda como mejora de seguridad).
- **Fuera:** recuperar contraseña, bloqueo por intentos fallidos.
- **Candidata a BDD.**
